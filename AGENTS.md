# Progressive Hub - instrucciones del proyecto

## Objetivo
Construir una pagina web promocional para dos productos:
1. Definitive Randomizer / pk3DS Progressive.
2. Pokemon Tracker Progressive.

El nombre comercial Progressive Hub es provisional.
El idioma de la pagina sera español.

## Diseño
- Estetica Dark Graphite.
- Portada compacta.
- Secciones horizontales alternadas.
- Azul suave para Definitive Randomizer.
- Rojo apagado para Pokemon Tracker Progressive.
- Apariencia moderna, cuidada y coherente.
- Responsive para PC, tablet y movil.
- Utilizar capturas reales y materiales autorizados.
- No crear imagenes generadas para sustituir capturas de los programas.
- Evitar el aspecto generico de landing page.

## Contenido
- Presentar claramente ambos productos y sus funciones.
- Mostrar capturas reales, caracteristicas y requisitos.
- Botones de descarga enlazados a GitHub Releases oficiales.
- No inventar versiones, estadisticas ni enlaces.
- Incluir Ko-fi: https://ko-fi.com/joanjuz
- Las donaciones son voluntarias.
- No presentar las versiones gratuitas como productos de pago.
- Contador publico de descargas, solamente con datos verificables.
- Estadisticas de visitas privadas para el administrador.
- No exponer datos personales ni informacion interna.

## Uso automatico de skills
Codex debe seleccionar y utilizar automaticamente las skills pertinentes
sin exigir que el usuario las mencione:

- design-taste-frontend: diseño e implementacion visual.
- image-to-code: implementar referencias o mockups proporcionados.
- redesign-existing-projects: auditar y mejorar interfaces existentes.
- web-design-guidelines: UX, accesibilidad y calidad web.
- playwright-cli: comprobaciones reales en navegador.

Utilizar solo las skills necesarias para cada tarea.
No invocar todas indiscriminadamente.
No sustituir pruebas reales por afirmaciones sin evidencia.

## Seguridad y conservacion
- Inspeccionar cambios Git existentes antes de modificar archivos.
- No eliminar cambios locales ni trabajo de otras tareas.
- No utilizar git reset --hard ni git clean -fd.
- No realizar commit, push, despliegues ni publicaciones sin autorizacion.
- No copiar ROMs, archivos de juego o materiales propietarios desde otros repositorios.
- Mantener este sitio independiente de los codigos fuente de las aplicaciones.
- No modificar Definitive Randomizer ni Pokemon Tracker desde este proyecto.

## Desarrollo
- Identificar el framework real antes de aplicar recomendaciones.
- Priorizar rendimiento, accesibilidad, SEO y responsive.
- Verificar navegacion, enlaces, errores de consola y visualizacion.
- Mantener una arquitectura sencilla y preparada para ampliaciones.
- Documentar las decisiones tecnicas relevantes.

## Escritura y voz editorial

- Utilizar automaticamente copywriting para crear textos de la web.
- Utilizar no-ai-slop para revisar los textos antes de entregarlos.
- Redactar en español natural, preciso y profesional.
- Evitar esloganes genericos y frases publicitarias vacias.
- No utilizar "Tu partida. Tus reglas", "lleva tu experiencia
  al siguiente nivel", "descubre un mundo de posibilidades",
  "el poder esta en tus manos" ni expresiones equivalentes.
- Cada titulo debe comunicar una funcion, beneficio concreto
  o informacion relevante del producto.
- Preferir verbos claros: editar, randomizar, configurar,
  descargar, registrar, consultar y sincronizar.
- No inventar caracteristicas, resultados ni estadisticas.
- Mantener el nombre real de cada producto.
- No llenar espacios visuales con texto innecesario.
- No generar esloganes si el usuario no los solicita.
- Priorizar claridad antes que creatividad publicitaria.
- Revisar los textos finales y eliminar cualquier frase
  que pudiera servir indistintamente para otro producto.
- Estas reglas se aplican a titulos, subtitulos, botones,
  tarjetas, descripciones, menus y metadatos SEO.
